# Project reference
Start with [current status](PROJECT_STATUS.md) when resuming work. Current user instructions and [AGENTS.md](../AGENTS.md) remain authoritative.

| Document | Purpose | Update trigger |
| --- | --- | --- |
| [PROJECT_STATUS.md](PROJECT_STATUS.md) | Coded, tested, installed, published and pending state | Work or delivery state changes |
| [ARCHITECTURE.md](ARCHITECTURE.md) | Module owners and data flow | Responsibilities change |
| [DATA_CONTRACTS.md](DATA_CONTRACTS.md) | Tokens, percentages, identity, time and unknowns | A calculation contract changes |
| [DECISIONS.md](DECISIONS.md) | Accepted product choices | The user changes direction |
| [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) | Manual checks and delivery verification | Delivery procedure changes |
| [VALIDATION.md](VALIDATION.md) | Dated evidence and coverage limits | Checks actually run |
| [SECURITY_REVIEW.md](SECURITY_REVIEW.md) | Trust boundaries and reviewed limits | A boundary changes or review runs |
| [GITHUB_POLICY.md](GITHUB_POLICY.md) | File hosting only, zero spending | Explicit policy change |
| [HISTORY_LESSONS.md](../HISTORY_LESSONS.md) | Historical lessons and releases | A useful lesson is demonstrated |

Keep stable rules in one place and link to them. Record evidence dates; a prepared test is not an executed test. Do not retain transcripts, credentials, raw logs, private fixture paths or personal machine paths in tracked documents.

## Project skills
Three discoverable skills live in the user's Codex skills directory:
- $gcd-usage-resume reconciles checkout, installed version and pending work.
- $gcd-usage-accounting checks token and allowance calculations against isolated fixtures.
- $gcd-usage-verify-release selects native checks and verifies manual delivery evidence.

Skills refer to these maintained documents rather than freezing current versions or temporary blockers inside their instructions.
